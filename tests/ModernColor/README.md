# 现代颜色菜单回归

从仓库根目录运行，无需安装 npm 包：

```powershell
node --test tests/ModernColor/*.test.cjs
node tests/ModernColor/ModernColorMenuPreview.cjs
```

测试直接加载模板的 `wwwroot/js/modern-color-layout.js`，验证点击新页面时不会被旧 `aria-current="page"` 误导、当前子项父级自动展开、非当前组保留手动状态、匹配 hash 的激活优先级、DOM 替换后的状态恢复及重复初始化的事件解绑。未匹配 hash 继续按当前 DOM 的激活标记处理。

预览程序绑定随机回环端口，加载模板实际 CSS、核心 JS 和 Blazor 适配脚本；静态依赖使用模板 `libman.json` 还原后的 `wwwroot/lib`。导航由合成菜单和模拟 `enhancedload` 实现，不等同于真实 Blazor 站点联调。

浏览器检查：

1. 打开输出的设置页，确认“系统设置”自动展开。
2. 手动收起“系统设置”，再点击“概览”，确认原分组仍收起。
3. 手动打开“系统维护”，导航到其他页面，确认该分组保持展开。
4. 回到“常规设置”，确认其父级展开；收起后刷新，确认再次自动展开。
5. 点击“重复初始化”，再切换菜单，确认点击只响应一次；检查桌面、手机宽度及亮暗主题。

验证后以 Ctrl+C 停止预览。
